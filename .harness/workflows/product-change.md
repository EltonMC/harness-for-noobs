# Product Change Workflow

Use when the outcome needs discovery, a design decision, multiple stories, or a changed authorization model.

1. Explore and validate the problem.
2. Produce a product brief or PRD with success criteria and non-goals.
3. Capture UX and architecture decisions.
4. Break work into independently verifiable stories.
5. Run readiness for the selected story. A `FAIL` blocks implementation; `CONCERNS` require an owner-accepted condition.
6. Create the downstream work item with intent gaps, irreversible actions, and footprint.
7. Execute each story through the quick-change workflow.
8. If implementation invalidates upstream intent, correct course upstream and rerun readiness before resuming.

When BMad is available, use its artifacts as inputs: `bmad-product-brief` or `bmad-prd`, `bmad-ux`, `bmad-architecture`, `bmad-create-epics-and-stories`, `bmad-sprint-planning`, `bmad-build`, `bmad-correct-course`, and `bmad-code-review`.
